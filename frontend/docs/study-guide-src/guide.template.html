BoardingEase Study Guide

Every file, every function, and where the data goes, from the HTML page to the model and back.

01Start here

BoardingEase helps DOrSU students find boarding houses near campus: search by name or barangay, filter by rent, then split the monthly cost with housemates.

How to run it

  1. Open the project folder in VS Code.
  2. Right-click index.html → Open with Live Server.
  3. Open DevTools (F12 or Cmd+Option+I) and keep the Console tab visible while you work.

⚠ Double-clicking index.html won't work. The page loads app.js as a module ([[L index.html 83 type="module"]]), and browsers block modules on file:// pages. You'll see a CORS error in the console. Always use Live Server.

How to read this guide

  • Grey chips like [[L js/model.js 10 applyFilters]] are file:line locations. Click one to jump to that exact line in the full source.
  • Blue function() links jump to that function's card in the reference. Every card lists who calls it and what it calls.
  • Badges show the MVC layer: Model View Controller.
  • Stuck on "where does this value come from?" Go to Follow the data, which walks through real clicks and keystrokes step by step.

Which app.js? This guide explains the week-5 version of the controller, which is now saved as js/app(old).js. The new js/app.js is the Lab 3 skeleton (defense on Monday, October 5), and index.html loads that one, so the page stays blank until you finish the lab. When this guide says "app.js", it means the code in app(old).js.

MVC in one paragraph

The code is split into three jobs. The Model (data.js, model.js) holds the data and the rules for filtering it, and never touches the page. The View files (views/) read what the user types and draw HTML, and they never import the model. The Controller (app.js) connects the two: when a view reports that something happened, a controller asks the model to update, then tells the view to re-draw. The MVC diagram shows this as a picture.

applyFilters()

[[L js/model.js 10 applyFilters]]

Rebuilds state.filtered from state.listings using the current search term and max rent. A listing is kept only if it passes both checks:

  • matchesQuery: the search box is empty, or the name or barangay contains the text (case-insensitive, because both sides are lowercased).
  • matchesRent: max rent is empty ("" means no limit), or monthlyRent <= Number(maxRent).

render(data)

[[L js/views/View.js 8 render]]

The main job of every view: take data and put it on the page.

  1. Guard clause: if there's no data, or it's an empty array, show the error/empty message instead and stop (return).
  2. Save the data in this._data.
  3. Ask the child class for the HTML (this._generateMarkup()).
  4. Clear the container, then insert the new HTML.

calculateCostPerHead(listing, people, withTransport)

[[L js/app(old).js 24 calculateCostPerHead]]

The money math. It first validates: it throws an Error if people isn't a whole number ≥ 1 [[L js/app(old).js 26 throw]] or is more than maxOccupants [[L js/app(old).js 28 throw]]. Then:

  • rent = monthlyRent ÷ people
  • utilities = 0 if included, otherwise sumUtilities ÷ people
  • transport = fareOneWay × 2 (round trip) × 22 days if ticked, otherwise 0 (not divided, because each person pays their own fare)
  • total = rent + utilities + transport

10Self-check

Answer in your head (or on paper) first, then open the answer.

1. What happens when resultsView.render([]) is called?

The guard in render sees an empty array [[L js/views/View.js 9 data.length]] and returns this.renderError(). With no argument, the message defaults to this._errorMessage, so the list shows the "No listings match…" box. _generateMarkup never runs.

2. Who calls applyFilters()? Does app.js ever call it?

Only setSearchTerm [[L js/model.js 29 applyFilters]] and setMaxRent [[L js/model.js 34 applyFilters]], both inside model.js. app.js never calls it directly: it only says "the search term changed", and the model decides to re-filter.

3. searchController is defined in app.js. On which line does it actually get called?

Inside SearchView: handler(e.target.value) [[L js/views/SearchView.js 9 handler]]. app.js only passes it over at [[L js/app(old).js 181 searchController]], without parentheses.

4. Why is View exported as a class, but SearchView as new SearchView()?

Other classes need to extends View, and you can't extend an object. Nobody uses a plain View anyway, because it has no _parentElement. SearchView is just used, and there's only one search form, so everyone should share one object. If each file did new SearchView(), you'd get duplicate listeners.

5. state.maxRent holds "5000", a string. Why, and what does "" mean?

Input values are always strings. "" means the box is empty, which the app treats as "no limit" [[L js/model.js 21 maxRent === ""]]. The conversion to a number happens only at the comparison, with Number(maxRent).

6. You click the image inside a card. How does the code still get the right id?

event.target is the <img>. .closest(".card") climbs to the <button class="card"> around it [[L js/app(old).js 144 closest]], and .dataset.id reads its data-id [[L js/app(old).js 148 dataset.id]].

7. Why does selectedListing() search state.listings instead of state.filtered?

If you select a card and then search for something else, that listing is no longer in filtered. Searching filtered would return undefined, and the breakdown would stop updating. Looking something up by id should search everything.

8. What would you see if _generateMarkup forgot its return?

markup would be undefined, and insertAdjacentHTML turns that into the text "undefined" on the page, with no error in the console.

9. Casa Amihan, 4 people, fare ticked: what's the per-person total, and why?

6500 ÷ 4 = 1625 rent, plus 2950 ÷ 4 = 737.5 utilities, plus 15 × 2 × 22 = 660 fare, gives 3022.5, which peso.format rounds to ₱3,023. The fare isn't divided, because everyone rides separately.

10. Which listing field does no code use yet?

amenities. See Where each field goes.

11. Which files never touch the DOM (no document, no HTML)?

data.js and model.js, the Model. That's rule #1 of MVC.

12. Why does typing in "Sharing with" call updateBreakdown and not renderDetail?

renderDetail replaces the whole panel, including the input you're typing in, so you'd lose focus after every keystroke. updateBreakdown replaces only the .breakdown box [[L js/app(old).js 138 breakdown.innerHTML]].
